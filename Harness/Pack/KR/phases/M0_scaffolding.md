# M0 — 기반/스캐폴딩 (예시)

**상태**: 예시(템플릿 시연용 — 실제 프로젝트에 맞게 교체)  **갱신**: {{YYYY-MM-DD}}

## 맥락
이후 모든 phase가 의존하는 레포·도구·경계를 세운다. 여기서 경계를 잘못 잡으면 INV-3 위반이 반복된다.

## 진입조건 (DoR)
- [ ] 저장소 생성, 패키지 매니저·런타임 버전 결정(`docs/ENVIRONMENT`)
- [ ] 디렉터리/모듈 경계 초안 결정(`docs/FILE_TREE`)

## 할 일
워크스페이스 설정 -> 빌드/번들 설정 -> 린트·포맷·타입 설정 -> 모듈 경계 룰(import 제한) -> 기본 CI(빌드/린트/타입체크).

## 참조
docs/FILE_TREE(경계), INVARIANTS INV-1·INV-2·INV-3.

## DoD (완료 게이트)
1. `{{빌드 명령}}` / `{{타입체크 명령}}` / `{{린트 명령}}` 전부 그린.
2. 금지된 모듈 상호 import 시 lint 에러로 차단됨(INV-3 준수) — 의도적 위반 샘플로 확인.
3. `.gitignore`가 시크릿·대용량 산출물을 제외(INV-1·INV-2 준수).

## 검증
`{{빌드}}` && `{{타입체크}}` && `{{린트}}`; 경계 위반 샘플 파일로 lint 실패 확인 후 제거.

## 증거 (통과 시 명령·핵심 출력 붙여넣기)
~~~
{{예: tsc --noEmit -> 0 errors / eslint . -> 0 problems / 경계 위반 샘플 -> eslint error 1건 확인}}
~~~

## 롤백 계획
스캐폴딩 커밋 단위로 분리해 두고, 설정 오류 시 해당 커밋만 revert.

## 리스크 / 미지수
- 경계 룰이 너무 느슨하면 이후 위반이 누적되어 발견이 늦어진다.

## 주의
설정이 "돈다"고 완료가 아니다. 경계 룰이 **실제로 위반을 막는지** 샘플로 확인할 것.
